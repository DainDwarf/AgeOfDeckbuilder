# Flood

**Line:** **Flood** — the Stone Age's event dealt on every map, no need named: _Lose the fields_ removes improvements inside the player's border, drawn seeded, one and one more for every ten turns; _Settle the floodplain_ adds the challenge **Floodplain** to the discard pile, which strikes as a hazard does and removes one improvement inside the border each turn it stays in the hand; _Dig channels_ pays production for each improvement the flood would take, more than one costs. Done when the event stands on both Stone schedules, a challenge may carry a strike resolved as a hazard's by one fixture test, the flood's removal has its fixture test, `npm test` is green with the coherence test among it, `e2e/flood.spec.ts` passes, and the pages below say so. **Scope:**

- In, the mechanism, one inert commit: a challenge may declare a strike, the same shape as a hazard's; the end-of-turn strike loop resolves a challenge's strike as it resolves a hazard's, one `strike` group each, and a challenge declaring none does nothing there as today. One fixture test: a challenge carrying a strike strikes at the end of a turn it is still in the hand, before the hand is discarded, and one carrying none does not; the fixture's standing challenge stays strikeless. One new rules helper beside the fire's: `count` improvements inside the player's border removed, each drawn seeded among every improvement standing on a tile the player's city holds, the city's own tile included, a tile carrying several counting each; fewer standing than asked, all go; none standing removes nothing and draws nothing and is no `runtime-error`. One fixture test: the count removed, the draw seeded, the tiles outside the border untouched, the shortfall and the empty case. The reading of how many the flood would take is the same helper's.
- In, the content, one commit with the measurement: the event `flood` in the Stone slice's events, answers declared in the order _Lose the fields_, _Settle the floodplain_, _Dig channels_; _Lose the fields_ costing nothing, reading `{ improvements: n }` with n the fewer of the improvements standing inside the border and one more one for every ten turns, landing that removal; _Settle the floodplain_ costing nothing, reading nothing, landing one copy of `floodplain` on the discard pile through the capture's reward helper; _Dig channels_ costing three production for each improvement _Lose the fields_ would take, read the same way, landing nothing. The card `floodplain`, kind challenge, influence three, its strike removing one improvement inside the border through the same helper. `flood: 1` on both Stone schedules, each written out. The texts and the lore above.
- Out: the `needs` field on events and the draw's filter on it, which the three Nomadic events still use and the board line **The Nomadic events' needs** removes; any change to those events or to Hunger; the numbers above, provisional, the balance pass's; a unit or a building touched by the flood, which takes improvements alone; the neutral's improvements, which the flood never touches; saves and campaigns, which need no care before the Bronze Age ends.
- Corner cases decided here: a flood with no improvement inside the border reads nought on _Lose the fields_ and _Dig channels_ alike, both do nothing, and the event is still dealt; a strike that finds no improvement removes nothing and the card stays; the city's own tile is inside the border and its improvements are taken like any; Fire discarding Floodplain spares that turn's strike, as it spares Hunger's.
- Reconcile: the challenge's strike goes through the hazards' strike loop as it is, the kind the one difference it reads; the challenge answer goes through the capture's reward helper as it is, one copy to the discard pile; the removal is new, and the pillage stays apart, stripping a tile whole where the flood takes one improvement among many; the border is read as every other rule reads it, the tiles the player's city holds.

**Traps:**
