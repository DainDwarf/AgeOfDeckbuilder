**Spec:** [`DOGMAS.md`](../../DOGMAS.md) → _Testing_, the bullet "**A spec opens on the save it wrote, on the game's content.**": after the sentence "A spec that tests the boot, the address or the save's own reading opens the way it tests.", add "A spec opens on the fastest speed the player can set, planted in the entry the game keeps it in as the save is; one that catches the screen inside a motion opens on the designed one." No player-facing sentence: the line changes nothing the player sees.

**Doc-impact:** none in `docs/`; `DOGMAS.md` → _Testing_.

**Scope:** In: the speed ×4 written to the browser entry the game keeps the animation speed in, at every load, by the one init-script door every spec's open already passes through — the one that gives the page its names — so the write stands before the game boots and before any init script a spec adds of its own; the entry's key exported from `src/ui/animation-speed.ts`, as the controls' and the save's are, and never re-typed in `e2e/`; a way for a test to open on the designed speed, ×1, called before its open, taken by exactly these seven tests: all three of `e2e/graphics.spec.ts` (the setting's own spec, which starts from what a fresh browser shows and whose third test asserts ×2 after one press), the rise caught mid-alpha in `e2e/ending.spec.ts`, the killed scout's shrink caught mid-scale in `e2e/fog.spec.ts`, the one test of `e2e/pointer-sweep.spec.ts`, the unit entered while the turn plays out in `e2e/console.spec.ts`, and the two tests of `e2e/end-of-turn-reading.spec.ts` that read the reckonings midway through a play-out; one new test in `e2e/graphics.spec.ts` that opens on the suite's speed and reads the three scenes at ×4 and the Animation speed row reading ×4, the one place the plant is asserted; the description of the turn budget's constant in `e2e/chronicle-screen.ts` reading what it now covers — measured 2026-10-30 locally, an end of turn 1.85 s at ×1 and 0.66 s at ×4, so 10 s is five times the designed turn and fifteen times the suite's. Out: the budget's numbers, which stay at 10 s a turn and 10 s cold start whatever the speed — a play-out that never ends is caught at 30 s as at 15, and CI's slowest budgeted test runs 10.3 s against 30; every `docs/` page; any assertion loosened — a test red at ×4 is reported, with its output, as a mid-motion reader the list missed or as a defect, and joins the seven only on the user's say; a speed past ×4 or a hold written as a speed — the two specs that pause a scene's tweens hold a motion to read it and keep doing so; any assertion of the speed in a shared open helper, which would run on every spec. Corner cases decided here: `e2e/refused-save.spec.ts` installs its refusal after the names door, so the plant's write runs first and the game, refused its storage, stands at ×1 as a refused browser does — nothing to add there; `e2e/failed-boot.spec.ts` opens through no helper and reaches no motion, left alone; a reload re-plants ×4, which is right since only the Graphics row writes the entry and every test pressing it opens on the designed speed; the opt-out leaves ×1 in the entry or writes it after the plant, either standing, since init scripts run in the order added and the last write wins. Reconcile: the plant follows the shape the controls are planted in — an init script writing the entry at every load — and not the save's, whose session mark exists so play's own write survives a reload, which the speed never needs; the designed-speed door is a sibling of the plant in `e2e/chronicle-screen.ts`, not a parameter on every open helper.

**Traps:** `animationSpeed()` in `src/ui/animation-speed.ts` reads the entry once a page load and caches it, so the write must land before the game boots: an init script does, a `page.evaluate` after the load does not. Playwright runs init scripts in the order they were added, at every navigation and reload. The hover rests, the small card's hand-over, `waitGameClock`, `PAST_REST` in `e2e/hover.spec.ts` and `IN_THE_AIR` in `e2e/broken-motion.spec.ts` all run on the scene clock, which the speed never scales (`docs/PHASER.md` → _Scenes and stacking_): their spans keep their meaning at ×4, and `IN_THE_AIR` at 1500 ms still outlasts any one stage's motion. `budget` is called by some sixty tests and its numbers do not move. The third test of `e2e/graphics.spec.ts` pauses the ui scene's tweens and reads `[2, 2, 2]` after one press, which holds only from ×1. The Testing bullet in `DOGMAS.md` is one line; Prettier refuses a wrapped one (`npm run lint`), and `npm run fmt` unwraps.
